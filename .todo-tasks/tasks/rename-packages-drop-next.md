# Rename packages: drop the -next suffix

## Motivation

`client-next` and `server-next` were named during a migration whose history no longer
matters — the legacy packages they migrated away from are gone. The directories become
`packages/client` and `packages/server`. The client's package name also changes:
`@luminous/canvas` → `@luminous/client`, because "Canvas" is about to name one app on
the platform (see the follow-up task `multi-app-platform-refactor`), not the wrapper.
`@luminous/server` already fits and keeps its name.

This is phase 1 of a two-task chain; phase 2 (`multi-app-platform-refactor`) builds on
the renamed paths.

## Do NOT

- Do NOT change any source code inside the packages — this is a rename and reference
  sweep only. No refactoring, no import reorganization beyond what the rename forces.
- Do NOT touch `.todo-tasks/` historical records (`.done/`, epic files) that mention
  the old names — they are records of past work.
- Do NOT hand-edit `.carta/MANIFEST.md` — run `carta regenerate` after editing docs.
- Do NOT rename the `@luminous/server` package name — only its directory moves.
- Do NOT use plain `mv` — use `git mv` so history follows.

## Plan

### 1. Move the directories

```
git mv packages/client-next packages/client
git mv packages/server-next packages/server
```

### 2. Rename the client package

In `packages/client/package.json`: `"name": "@luminous/canvas"` → `"name": "@luminous/client"`.
First confirm nothing imports `@luminous/canvas` (grep; expected: no importers — it is
an app, not a library).

### 3. Sweep references in build wiring

- `tsconfig.json` (root, lines 5-6): the two project-reference paths.
- `justfile`: every `packages/client-next` and `packages/server-next` (lines 26, 27,
  38, 39, 56, 59, 63, 80, 92, 96, 100, 108, 112).
- `scripts/analyze-solidjs.ts`: comment at line 10, the import of
  `../packages/server-next/src/types.js` at line 33, and the default target path at
  line 1303.
- `.github/workflows/release-web.yml`: lines 32, 35, 49.

### 4. Sweep references in docs

- `CLAUDE.md`: the Project Structure section names `server-next`, `client-next`, and
  `@luminous/canvas` — update paths and the package name.
- `.carta/` docs: replace `packages/client-next` → `packages/client`,
  `packages/server-next` → `packages/server`, bare `client-next`/`server-next`
  mentions, and `@luminous/canvas` → `@luminous/client` where it names the client
  package. Affected files include docs under `01-vision/03-milestones/` and
  `02-design/` (find them with grep). Then run `carta regenerate`.

### 5. Regenerate / sweep generated canvases

- `just analyze` regenerates `.canvases/solidjs-analysis.canvas.json` with the new
  paths.
- `.canvases/pipeline-flowchart.canvas.json`: textual replace of the old paths.

### 6. Refresh the lockfile

`pnpm install` — the lockfile's workspace importer paths change with the directories.

### 7. Final sweep

Grep the repo (excluding `node_modules`, `.git`, `.todo-tasks`) for `client-next` and
`server-next`; expect zero hits.
