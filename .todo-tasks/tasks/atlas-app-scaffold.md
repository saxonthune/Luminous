# Scaffold the Atlas app

## Motivation

Atlas (doc01.07) is the third Luminous product, after Canvas and the Dataflow
Designer. It has product docs — an Idea (doc01.07.01) and the braincrawl case
(doc01.07.02) — but no code. This task lays the first end-to-end path: an app
that appears in the header, picks a file, and renders it.

Read `.rhidoc/01-product/07-atlas/01-idea.md` and `02-braincrawl-case.md` before
starting. Two claims there bind this task: an atlas is **authored over time and
not regenerated by pipeline scripts**, and its nodes descend from the Dataflow
Designer's Box — prose intention plus an optional language-specific contract.

The Dataflow Designer (`packages/client/src/apps/dataflow/`) is the template.
It is the precedent for an app that owns a pack-less document format and starts
read-only. Follow its shape closely.

## Do NOT

- **Do NOT spread `tidyLayout` or cactus's `TidyNode` through the app.** Layout
  is a placeholder here and will be replaced by a relation solver. All layout
  goes behind one function in one file (see step 4). Everything outside that file
  works in Atlas's own vocabulary. This is the single most important constraint
  in the task — a diffuse layout dependency is the failure mode.
- **Do NOT introduce a pack file, `View`, `nodeRoles`, `edgeRoles`, or
  `KindId`.** Atlas has no pack. Parent/child is a literal field, not a per-view
  relation computed from contain-role edges. Do not call `evaluateContainment`,
  `evaluateView`, or `buildGraph`, and do not use `CanvasHost`.
- **Do NOT make Atlas writable.** No edit mode, no write/copy/move/delete
  routes, no picker row actions. Leave the existing write route guards in
  `packages/server/src/index.ts` untouched so `.atlas.json` is rejected there by
  construction.
- **Do NOT add x/y/w/h to the document format.** Positions are computed, never
  persisted — the same rule Dataflow and Canvas already hold.
- **Do NOT add a `kind` field to Atlas nodes.** Without a pack there is no
  vocabulary to resolve it against. Deferred deliberately; see Notes.
- **Do NOT mechanically transcribe braincrawl's 75-node CLI graph.** The sample
  is authored, not ported. See step 6.
- **Do NOT reuse `.dataflow.json` types by import or extension.** Atlas owns its
  format. Duplicating a small type is correct here; coupling the two formats is not.
- **Do NOT edit `.rhidoc/` or `MANIFEST.md`.** Docs follow in a later task.

## Plan

### 1. Atlas document types — `packages/core/src/atlas/types.ts`

Mirror the shape and terseness of `packages/core/src/dataflow/types.ts`.

```ts
export interface AtlasDocument { v: number; nodes: AtlasNode[]; edges: AtlasEdge[]; }
export interface AtlasNode {
  id: string;
  name: string;
  parent?: string;
  description?: string;
  contract?: AtlasContract;
}
export interface AtlasContract { format: string; text: string; }
export interface AtlasEdge { from: string; to: string; label?: string; }
```

Declare `AtlasContract` locally — do not import `ContractBlock` from
`../dataflow/types.ts`. The formats are independent even where they agree.

### 2. Parser — `packages/core/src/atlas/document.ts`

Follow `packages/core/src/dataflow/document.ts` closely; it is the model for
every choice here. Hand-rolled, no Zod/Ajv.

Export:
- `emptyAtlasDocument(): AtlasDocument` → `{ v: 1, nodes: [], edges: [] }`
- `parseAtlasDocument(text): { ok: true; doc } | { ok: false; issues: string[] }`
- `serializeAtlasDocument(doc): string` — explicit field-by-field serializers,
  2-space JSON, trailing newline. Round-trips.

Validation, accumulating **all** issues rather than failing on the first:
- Strict unknown-field rejection, using the `TOP_LEVEL_FIELDS` / `NODE_FIELDS` /
  `CONTRACT_FIELDS` / `EDGE_FIELDS` const-set + `unknownFieldIssues` pattern from
  `dataflow/document.ts:11-16`.
- Duplicate node id.
- `parent` references an unknown node id.
- **Parent cycle.** Walk each node's parent chain with a visited set. Report the
  cycle's node ids in the issue text. Roughly 15 lines — do not reach for
  `evaluateContainment`.
- Edge `from`/`to` reference unknown node ids.

Single-parent is structural: `parent` is one optional string, so no check is needed.

### 3. Barrel + export — `packages/core/src/atlas/index.ts`

Mirror `packages/core/src/dataflow/index.ts`. Then add to
`packages/core/package.json` `exports`, next to `"./dataflow"`:

```json
"./atlas": "./src/atlas/index.ts"
```

### 4. The layout seam — `packages/client/src/apps/atlas/layout.ts`

**This file exists to be replaced.** It is the only place in the app that may
import from `@luminous/cactus`'s layout modules or name `TidyNode`.

Export exactly one function:

```ts
export function layoutAtlas(doc: AtlasDocument): Map<string, { x: number; y: number }>
```

Implement it by mapping `AtlasNode` → `TidyNode` (`{ id, w, h, parentId: node.parent ?? null }`)
and calling `tidyLayout`. Node sizes may be a constant for now; put any size
constant in this file.

Open the file with a comment stating that layout is a placeholder pending the
relation-based layout language, and that the export signature is the seam —
`AtlasDocument` in, positions out, no cactus types crossing the boundary.

### 5. App — `packages/client/src/apps/atlas/`

- **`AtlasApp.tsx`** — model directly on `dataflow/DataflowApp.tsx`. Shell state
  machine, `DocumentPicker`, load/parse, WebSocket reload. Pass `'.atlas.json'`
  to `fetchServerSources` (`sources/serverSources.ts:22`) and `heading="Atlases"`
  to `DocumentPicker`. Read-only: pass **no** row actions, and omit
  `dispatchDoc` / `writeDocument` / `ownWritesInFlight` entirely.
- **`projection.ts`** — `AtlasDocument` → cactus `EdgeDeclaration[]`, plus node
  content shaping. Does **not** compute positions; it calls `layoutAtlas`.
- **`AtlasCanvas.tsx`** — model on `dataflow/DataflowCanvas.tsx` but strip edit
  mode, context menus, `onAction`, drag, and `nodeOverrides`. Keep the
  `DataflowNodeLayer` pattern: a child component is required because
  `useCanvasContext()` only resolves inside `<Canvas>`'s children (see the
  comment at `DataflowCanvas.tsx:57-61`). Render nesting via `NodeContainer`.
  Render `description` as markdown with `marked`, mirroring `BoxContent.tsx:66-68`
  including its security comment; show `contract.text` in a `<pre>`.
- **`registry.ts`** — add `{ id: 'atlas', label: 'Atlas', component: AtlasApp }`
  to the `APPS` array. This is the whole client registration.

### 6. Sample data — `.canvases/braincrawl.atlas.json`

Hand-author roughly 30 nodes. **Author it; do not transcribe.** Source material
to read for facts, in the sibling repo at `../braincrawl/`:
- `.luminous/cli-grammar.graph.json` — commands and flags, nested by `cli.contains`
- `.luminous/braincrawl.dataflow.json` — 7 boxes, 13 flows, with descriptions and contracts
- `.rhidoc/01-product/01-glossary.md` — the controlled vocabulary for naming

Aim for:
- A CLI branch nested three deep (e.g. `braincrawl` → `openalex` → `get` → its flags),
  covering two or three providers so the repetition across them is visible.
- The storage layers (L1 Library, L2 Catalog, L3 Research Collection) as nodes
  with prose descriptions.
- The dataflow boxes, with `description` and `contract` carried over.
- Edges between them — e.g. a command to the store it writes.
- Every container holding at most ~25 children.

Ids are derived, readable paths, following braincrawl's own convention
(`command.braincrawl.openalex.get`) and `dataflow/addBox`'s name-derived ids.

## Out of Scope

- Layout relations, the relation vocabulary, and the solver — `layout.ts` is a
  placeholder with a deliberate seam
- MCP tools for Atlas
- Editing, in any form
- Comparison of an atlas against source code or generated artifacts
- A pack file, node kinds, tags, or views
- The Atlas glossary and UI requirements docs — a later task

## Notes

- **The layout seam is the thing to review.** If `TidyNode` or `tidyLayout`
  appears anywhere but `layout.ts`, the task has failed its main constraint even
  if everything renders.
- `kind` is deliberately absent from `AtlasNode`. Without a pack there is nothing
  to resolve it against, and the glossary task that follows should decide whether
  Atlas needs kinds at all. Adding it speculatively would prejudge that.
- `TidyNode.parentId` is already the standard parent/child field cactus wants.
  Dataflow sets it to `null` always and fakes grouping with `clusterId`; Atlas is
  the first app to use it as intended. Do not copy Dataflow's `clusterId` usage.
- Watch for the `useCanvasContext()` constraint when stripping
  `DataflowCanvas.tsx` — the child-component split is load-bearing, not incidental.
- `.canvases/` also holds legacy `.canvas.json` files that the server does not
  discover. Do not confuse them with `.graph.json`.

## Surface after this phase

- `@luminous/core/atlas` exports `AtlasDocument`, `AtlasNode`, `AtlasContract`,
  `AtlasEdge`, `emptyAtlasDocument()`, `parseAtlasDocument()`,
  `serializeAtlasDocument()`.
- `AtlasDocument` is `{ v: 1, nodes: AtlasNode[], edges: AtlasEdge[] }`. An
  `AtlasNode` is `{ id, name, parent?, description?, contract? }` — a flat list
  with an optional parent id, no `kind`, no `tags`, no coordinates. An
  `AtlasEdge` is `{ from, to, label? }`.
- `packages/client/src/apps/atlas/layout.ts` exports
  `layoutAtlas(doc: AtlasDocument): Map<string, {x, y}>` — the only place cactus
  layout is referenced, and the seam the relation solver replaces. Its internals
  (currently `tidyLayout`) are not part of this surface.
- The app is registered as `{ id: 'atlas', label: 'Atlas' }` in
  `packages/client/src/apps/registry.ts` and reachable at `/?app=atlas`.
- The server discovers, reads, and watches `*.atlas.json`. It does **not** write,
  copy, move, or delete them — those routes reject `.atlas.json`, and Atlas is
  read-only until a later phase changes that deliberately.
- `.canvases/braincrawl.atlas.json` exists as an authored sample and is parsed by
  `packages/core/tests/atlas/examples.test.ts`.
- Negative space: no pack, no `View`, no node kinds, no tags, no MCP tools, no
  edit path. Atlas does not call `evaluateContainment`, `evaluateView`,
  `buildGraph`, or `CanvasHost`. Dataflow and Canvas are entirely unchanged.
